# 2026-11-12 审查意见处置

对象是旧 head `e52e762965cec23bc4cbf8341619493b8cba9c0f`。官方 deepseek-flash 审查接口返回 HTTP 200。研发对照实跑做了核查。下面是修复前的独立复现和处置，不是新 head 的通过结论。后续仍会补审这次差异。

## 1. 缩进的 frontmatter 分隔符

复现成立。依赖写在缩进的 `---` 之前、服务器声明写在其后时，旧实现退出码 0，矩阵只有工具满足，没有服务器行。依赖和服务器声明都在分隔符之后时，旧实现是退出码 1，并不是这条假通过。

处置：采纳。只有行首且整行正好为 `---` 才结束 frontmatter。修复后该形状退出码为 1，并保留服务器行。

## 2. `--skill` 根路径是目录符号链接

复现成立。有效目录链接退出码 0 并显示满足。断链当时报成找不到目录。祖先路径中的链接，以及先经过链接再用 `..` 返回的路径，也会被跟随并通过。子目录链接、`SKILL.md` 链接和快照文件链接原本就会拒绝。

处置：采纳。参数原文的每一段只要是符号链接就拒绝，退出码 2，不显示满足。扫描中发现的链接仍拒绝。不把“当前工作目录怎样进入”算进参数检查。

## 3. 快照版本 `1.0` 和 `true`

复现成立。两者都退出码 0，并给出与整数 1 相同的满足矩阵。原因是 Python 把这些值和 1 看成相等。这是非法封装被接受，所用工具表本身是满足的。

处置：采纳。版本必须是整数 1，布尔值和浮点都拒绝，退出码 2。

## 4. 嵌套不可读目录

复现成立。非 root 环境下，合法 skill 旁边有权限为 0 的空目录时，旧实现退出码 0，只报告合法 skill。

处置：采纳。`os.walk` 的错误要回传。整轮退出码 2，已发现的行改为未判定。

## 5. 1,000,000 字节和 1 MiB

复现成立。旧代码在超过 1000000 字节时拒绝，所以 1000001 字节会报过大，而 1 MiB 是 1048576 字节。这会误拒，不是依赖假通过。

处置：采纳。上限改为明确常数 1048576 字节，并写入范围说明和测试。

## 6. 扫描错误丢掉同根合法 skill

复现成立。同一根里既有合法 skill 又有子目录符号链接时，旧实现退出码 2 且标准输出为空。评估阶段的混合输入则会把满足改成未判定。两边不一致。

处置：采纳保留已发现行。整轮仍是退出码 2，这些行显示未判定，不显示满足。链接目标不读取。

## 7. FIFO `SKILL.md`

复现成立。对 FIFO 运行时在数秒内没有返回，超时结束，标准输出和标准错误都为空。同一检查下，快照 FIFO 不会挂起，旧实现退出码 2，原因是它不是普通文件。

处置：采纳。`SKILL.md` 和快照都在读取前要求普通文件，退出码 2。FIFO 不再打开。

## 8. `license` 等顶层字段

复现成立。带 `license: MIT` 且依赖本身满足的技能退出码 1，原因是未知字段。

处置：部分采纳。允许但不解释 `license`、`compatibility`、`metadata`、`allowed-tools`。未知依赖组合仍然拒绝。这不是完整规范支持，范围说明里写明了这个边界。
