# submodule-audit

进一个根目录，递归发现其中的本地 git 仓库，逐个回答子模块到底健不健康，输出一张按仓库分组、按严重程度排序的表。只读报告，不 init、不 update、不改配置。

1. 用法：`python3 submodule-audit.py <根目录> [--json]`，退出码 0 表示扫完（有问题也为 0，问题写在表里），根目录不存在或不是目录时退出码为 2。
2. 检查项：未初始化（`status` 前缀 `-`）、提交不一致（前缀 `+`）、合并冲突（前缀 `U`）、URL 漂移（`.gitmodules` 与 `.git/config` 的 URL 对照，缺失一方也单独报）、嵌套子模块漏初始化（`status --recursive` 覆盖嵌套层）、父仓库索引记的提交在子模块远端不存在、子模块远端不可达（不可达、404、认证失败分开标）。
3. 远端探测的做法：先跑 `git ls-remote <远端>` 看 ref 尖端，提交在尖端里即存在；不在尖端时再把单个 SHA 取到临时裸仓库里核对对象在不在。注意 `git ls-remote <远端> <SHA>` 这样查不到东西，因为 ls-remote 的模式只匹配分支名、不匹配 SHA，传 SHA 永远返回空，会把健康子模块也误报成远端不存在；临时裸仓库在扫描目录之外、跑完即删。
4. 红线：只读，不运行 `git submodule init`、`update`、`sync`，不改 `.gitmodules`、不改 `.git/config`，不删任何对象；远端 URL 只打印脱敏形式（主机加路径，带用户名密码的 URL 只显示主机）；建议命令只打印不执行。
5. 已知局限：`ls-remote` 需要网络，离线时第 6、7 项记“未核实”，不报假结论；认证失败与不可达在没有凭证时难以严格区分，按 git 报错文本分开标，不确定时写“疑似认证失败”；浅克隆的子模块可能因历史不全被误判为提交不存在，遇到先标“浅克隆，结论仅供参考”；只看本地克隆视角，父仓库远端与子模块远端是否一致不在本版范围。

演示：[demo.py](./demo.py)，运行 `python3 demo.py`，只在它自己的临时目录里造一个示例根目录（一个健康仓库、一个未初始化、一个提交不一致），打印审计表，然后清掉临时目录，不改任何文件。

自测：`python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest -q`
