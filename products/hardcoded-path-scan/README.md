# hardcoded-path-scan

进一个仓库目录，一次扫出代码与配置文件里写死的绝对路径，按文件分组列出来，只读报告，不改文件。写死路径有两个坏处：换一台机器就跑不通；还容易把本机用户名、盘符这些个人信息带进公开仓库，提交前扫一次，两个问题一起防。

1. 用法：`python3 hardcoded-path-scan.py <仓库目录> [--json]`，默认按文件分组打表，每行四列（文件、行号、命中的路径、路径种类），并附一句建议方向（改成相对路径、环境变量或配置项）；末尾一行汇总（扫了几个文件、命中几条、跳过了几个文件及原因）；加 `--json` 则输出命中对象数组（文件、行号、路径、种类），汇总打到 stderr。
2. 判定分工：三类路径各一条正则，盘符（`C:\...`、`D:/...`）、UNC（`\\server\share\...`）、POSIX（`/home/...`、`/Users/...`、`/etc/...`、`/var/...`、`/opt/...` 等，单独一个 `/` 不算）；只扫扩展名白名单（`.py`、`.js`、`.ts`、`.jsx`、`.tsx`、`.json`、`.yaml`、`.yml`、`.toml`、`.ini`、`.cfg`、`.xml`、`.sh`、`.bat`、`.ps1`）；跳过 `.git`、依赖与构建目录（`node_modules`、`.venv`、`venv`、`__pycache__`、`dist`、`build`）和含 NUL 字节的二进制文件。
3. 不误报：行首 shebang（`#!/usr/bin/env python3`）不列，`http://`、`https://` 开头的网址先去掉再匹配，`.md` 按扩展名不在扫描范围；同一文件多行命中逐行列出，不合并去重。
4. 红线：只读，不改文件、不删文件、不装依赖；只输出命中的路径片段、文件与行号，不打印整行内容；判定只认正则命中的文本，拿不准的标“疑似”，建议只写字不改文件。
5. 已知局限：正则只能认文本形态，分不清路径在运行时是否真的会被用到，死代码里的路径也会被报出来；拼接出来的路径查不到（`os.path.join(os.environ["HOME"], "data")` 这种写法不在本版扫描范围内，这是好事，但也要写明）；字符串跨行拼接、转义后的反斜杠可能漏报，本版只做单行正则，不做语法解析；大仓库单次扫描可能慢，不做缓存。

演示：[demo.py](./demo.py)，运行 `python3 demo.py`，只在它自己的临时目录里造一个示例仓库，打印分组表，然后清掉临时目录，不改任何文件。

自测：`python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest -q`
